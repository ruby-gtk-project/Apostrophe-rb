# Translation parity — Apostrophe

Method: the `translation-parity` skill. Upstream (`origin/main`) ships
`po/LINGUAS` (33 locales), `po/POTFILES.in` (37 source files contributing
strings — not the 42 the stale `component-inventory.md` quotes; recounted
directly against `git ls-tree`), and 33 `.po` catalogues, e.g. `po/en_GB.po`
with 153 `msgid` entries (no checked-in `.pot` template — it's generated by
the Meson build, consistent with Meson-based GNOME apps).

## Port status

```
find po -maxdepth 1    →  (nothing; po/ does not exist on `ruby`)
```

The `ruby` branch has **no `po/` directory at all** — no `LINGUAS`, no
`POTFILES.in`, no `.pot`, no `.po` files, no `gettext`/`GetText` calls
anywhere in `lib/` or `exe/` (`grep -rn "gettext\|_(\|N_("` over `lib/ exe/`
returns nothing — reconfirmed below).

## Every upstream msgid

153 msgids live in the reference catalogue (`en_GB.po`, counted directly,
not estimated). **0 of 153 survive in the port.** This is not a partial
gap, a rounding error, or a few stragglers — it is the entire translation
system: no extraction tooling is wired to any ported string, and no ported
widget calls a translation function. Every user-facing string identified
in `component-identification.md` and `component-parity.md` (menu items,
tooltips, dialog bodies, button labels, empty-state text) is a hardcoded
English literal in the Ruby source today.

## Is extraction infrastructure at least in place for later?

Partially. `component-inventory.md` notes the flake's dev shell carries
`rxgettext` and the Rakefile has a `rake pot` task — reconfirmed by
`flake.nix:192`, which comments on `rxgettext` as "the extractor `rake pot`
drives." The extractor exists in the devShell; it has nothing to extract,
because 0 strings in `lib/` are wrapped in a translation call
(`grep -rn 'gettext\|_("\|N_(' lib/ exe/` returns no matches at all). Having
the tool on `PATH` is not translation infrastructure if no string in the
codebase is marked for it.

## Verdict

Translation parity: **0%**. Not "most strings survived with a few gaps" —
no msgid survived, no locale survived, no extraction call exists anywhere
in the ported source, and nothing in `.reports/` or prior commits claims
otherwise. This matches `component-inventory.md`'s own §38 note ("the port
has no catalogue") and should be read as a hard, total gap rather than a
backlog item buried in a components table.
